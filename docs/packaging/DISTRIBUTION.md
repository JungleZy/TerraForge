# TerraForge - 可执行文件分发说明

本目录包含 TerraForge的独立可执行版本。

## 快速开始

### Windows
1. 解压 `terraforge-windows.zip`
2. 双击 `terraforge.exe`
3. 打开浏览器访问 `http://localhost:5000`

### macOS
1. 解压 `terraforge-macos.tar.gz`
2. 打开终端，进入解压后的文件夹
3. 运行：`./terraforge`
4. 打开浏览器访问 `http://localhost:5000`

### Linux
1. 解压 `terraforge-linux.tar.gz`
2. 打开终端，进入解压后的文件夹
3. 运行：`./terraforge`
4. 打开浏览器访问 `http://localhost:5000`

## 功能特性

- 无需安装 Python
- 无需安装依赖
- 可移植 - 可复制到任何机器运行
- 所有依赖已打包

## 系统要求

- **Windows**: Windows 10 或更高版本（64位）
- **macOS**: 仅支持 Apple Silicon (arm64)。发布包在 Apple Silicon 机器上构建，Intel Mac 无法运行，需自行[从源码构建](../BUILD.md)
- **Linux**: 与 ubuntu-latest（发布包的构建环境）同等或更新的 64 位发行版

## 目录结构

```
terraforge/
├── terraforge(.exe)    # 主程序
├── templates/              # Web 界面模板
├── static/                 # CSS、JS、图片
├── gdal-data/              # GDAL 数据文件
├── proj-data/              # PROJ 坐标系数据文件
├── data/                   # 数据库（自动创建）
├── downloads/              # 下载的地图（自动创建）
└── cache/                  # 瓦片缓存（自动创建）
```

**移动或复制时必须整个 `terraforge/` 目录一起搬。** 程序在自身可执行文件所在的目录里查找 `gdal-data/` 和 `proj-data/`（坐标转换与栅格读写的必需数据）。只把可执行文件单独拷出来，启动时会直接报错退出：`Corrupt bundle: missing GDAL/PROJ data directories`。

## 配置说明

应用首次运行时会自动创建必要的目录：
- `data/` - SQLite 数据库
- `downloads/` - 下载的地图文件
- `cache/` - 瓦片缓存以提高性能

## 故障排除

### 端口已被占用

⚠️ **切勿同时运行两个 TerraForge 实例。**

第二个实例确实会因为端口冲突而退出，但它在退出**之前**已经完成了数据库初始化、启动清扫和四条任务管线的孤儿任务恢复——这些动作都发生在绑定端口之前。后果是：它会删掉第一个实例**正在使用**的临时工作目录，并把第一个实例正在跑的任务状态改写成"中断后恢复"的样子。正在下载的任务因此损坏，且无法自动挽回。

所以，如果启动时提示端口被占用：先确认不是自己已经开着一个 TerraForge（检查任务管理器 / `ps`），再去处理其他占用 5000 端口的程序。

监听端口固定为 5000，**不可配置**——配置页面和配置文件里都没有改端口的选项，不必去找。

### 防火墙警告

首次运行时系统防火墙会询问是否允许接受传入连接。**这不是一个例行的无害提示，请先读完下面这段再决定。**

TerraForge 监听 `0.0.0.0:5000`，即接受来自局域网任意机器的连接，且**没有任何登录或鉴权机制**。它的 API 可以读写本机任意磁盘路径、并能删除目录。程序启动时还会在控制台主动打印局域网访问地址。点"允许"，等于把上述能力开放给同一网络内的所有人。

建议：

- 在**咖啡馆、酒店、公司公共 Wi-Fi 等不受信任的网络**下，选择"拒绝"，或只勾选"专用网络"。
- 拒绝**不影响任何功能**——本机浏览器通过 `http://localhost:5000`（即 127.0.0.1）访问，走的是回环地址，不经过防火墙的入站规则。
- 只有在你确实需要用**另一台设备**访问本机的 TerraForge 时，才需要允许，并请确保处在可信网络中。

### macOS 安全警告

从网络下载的未签名程序会被 macOS 标记隔离属性，表现为"已损坏，无法打开"或直接被拦截。进入解压出的 `terraforge` 文件夹，执行：

```bash
xattr -cr .
```

注意这里清的是**整个目录**（`.`），而不是只清可执行文件——同目录下的动态库同样带着隔离标记，漏掉它们程序照样起不来。

如果仍被阻止：

1. 打开"系统设置" → "隐私与安全性"
2. 在底部找到被拦截的提示，点击"仍要打开"

注意：如果你用的是 **Intel Mac**，报错的根源是架构不匹配（发布包为 arm64），不是安全策略——反复调整安全设置没有用，请参见上文「系统要求」。

### Linux 权限错误
如果遇到权限错误：
```bash
chmod +x terraforge
```
