# 瓦片请求连接池隔离设计

## 背景

TerraForge 首页使用 Cesium 加载底图、任务瓦片、等高线和 terrain。浏览器通过 HTTP/1.1 访问时，通常只为同一个 origin 建立约 6 条并发连接。冷底图请求还可能在服务端同步回源数秒，因此瓦片请求会占满 `http://<host>:5000` 的连接池，使任务 API、配置 API 和 Socket.IO 握手在浏览器中排队。

该瓶颈发生在浏览器到应用的连接池，不是 Flask 只能处理 6 个请求。提高服务端下载任务的 `concurrent_downloads` 无法解决它。

## 目标

1. 将高并发瓦片请求与页面、API、Socket.IO 请求分配到不同的浏览器 HTTP/1.1 连接池。
2. 保持当前 Flask-SocketIO、Werkzeug 和 Nuitka 桌面分发架构，不要求用户安装反向代理或证书。
3. 专用瓦片端口不可用时自动退回现有同源路径，功能优先于性能。
4. 保持现有瓦片 URL、缓存头、权限边界和任务数据格式兼容。
5. 覆盖底图、地图任务瓦片、等高线、terrain、hillshade 和基础 terrain 父级引用，避免部分请求绕回主端口。

## 非目标

- 本次不把应用迁移到 ASGI、Quart、Hypercorn 或其他 HTTP/2 服务栈。
- 本次不内置 Caddy/Nginx，也不处理公网 TLS 证书签发。
- 本次不实现瓦片批量协议、自定义 Cesium ImageryProvider 或 Service Worker 缓存。
- 本次不重构服务端地图/DEM 下载并发模型。
- 本次不通过降低 Cesium 并发来牺牲地图加载速度，除非专用 origin 降级后仍需另行保护。

## 方案选择

### 方案 A：专用瓦片 origin（采用）

主应用继续监听 `5000`，新增只服务瓦片资源的 `5001`。浏览器把两个端口视为不同 origin，因此分别获得 HTTP/1.1 连接池。该方案对现有桌面版侵入最小，不增加外部部署依赖。

### 方案 B：HTTP/2 反向代理（暂不采用）

Caddy/Nginx 可在浏览器侧通过 HTTPS/HTTP/2 多路复用所有请求，是服务器部署的长期方案。但它需要证书、WebSocket upgrade、上传限制和超时配置，不适合作为当前桌面版默认运行方式。

### 方案 C：限制 Cesium 并发并聚合 API（仅作后备）

降低 `Cesium.RequestScheduler.maximumRequestsPerServer` 并把四个活动任务接口合并，可以减少 API 饥饿，但不能解除 HTTP/1.1 的同源限制，还会降低地图冷加载吞吐。本次不作为主方案。

## 架构

### 主服务

主服务保持现状：

- `http://<host>:5000/`：页面和静态前端资源；
- `http://<host>:5000/api/...`：REST API；
- `http://<host>:5000/socket.io/...`：Socket.IO 握手、轮询和 WebSocket；
- 当专用瓦片服务未启动或客户端不可达时，继续兼容现有同源瓦片路径。

### 瓦片服务

应用通过 `src/core/tile_server.py` 在后台线程启动第二个 threaded Werkzeug server，复用同一个 Flask app 和现有路由逻辑，只允许以下资源：

- `/basemap/...`
- `/tiles/...`
- `/terrain/...`
- `/contour/...`
- `/tile-health`

其余路径在 `5001` 返回 `404`，避免意外暴露 API、页面和 Socket.IO。瓦片响应保留原有缓存头，并增加允许主页面跨 origin 读取所需的 CORS 响应头。

`/tile-health` 只返回轻量、无状态的成功响应，用于客户端确认该 origin 真正可达。它不访问数据库、磁盘瓦片或第三方底图源。

### 生命周期

1. `run_server()` 启动主服务前尝试绑定专用瓦片端口。
2. 绑定成功后记录当前瓦片端口；绑定失败时记录警告并保持端口状态为空。
3. 主服务无论瓦片端口是否成功都继续启动。
4. WSGI import 路径不隐式启动后台端口；此时自然使用同源瓦片路径。
5. 应用退出时，瓦片服务线程随进程结束，不引入独立守护进程。

默认端口为主端口加一，即 `5001`。端口值由后端统一提供，前端不散落硬编码。

## 前端 URL 解析与启动流程

### 统一 URL 入口

`static/js/ui.js` 提供唯一的瓦片 URL 解析函数。地图、历史地图、任务预览、terrain、hillshade 都必须经过该函数，业务模块不得自行拼接端口。

输入为应用内绝对路径时：

```text
/basemap/1/2/3 -> http://<当前页面主机>:5001/basemap/1/2/3
```

未启用专用端口时保持原路径，由浏览器解析到主 origin。

外部完整 URL 不应被错误改写。由后端生成的应用内 terrain 父级地址应规范化为 `/terrain/...` 形式，使它自动继承当前 `layer.json` 的 tile origin。

### 可达性探测

前端在创建首个 Cesium Viewer 之前完成一次最长 1 秒的健康探测：

1. 后端未提供瓦片端口时直接选择同源模式。
2. 页面为普通 HTTP 时，探测 `http://<当前页面主机>:<tile_port>/tile-health`。
3. 页面为 HTTPS 而专用端口没有可用 HTTPS origin 时，不尝试明文混合内容，直接选择同源模式。
4. 探测在 1 秒内成功后，本页面会话内所有应用瓦片 URL 使用专用 origin。
5. 超过 1 秒、网络错误、CORS 错误或非成功状态时，本页面会话内回退同源模式。

这 1 秒是健康探测的硬上限；实现使用可取消请求，超时后不保留后台悬挂请求。

探测结果只保存在当前页面运行时，不写入持久配置。这样端口、防火墙或代理环境变化后，刷新页面即可重新判断。

### 初始化顺序

首页和历史页应在健康探测完成后再创建 Cesium Viewer，避免 Viewer 已经开始同源请求后再切换 origin。API 初始化可以并行进行，不需要等待地图瓦片下载完成。

## 请求数据流

专用端口可用时：

```text
Browser
  ├─ :5000 -> HTML / JS / CSS / REST API / Socket.IO
  └─ :5001 -> basemap / task tiles / contour / terrain / hillshade
```

专用端口不可用时：

```text
Browser
  └─ :5000 -> 所有现有请求
```

底图缓存命中仍由现有 Flask 路由处理。专用服务复用同一个 app，因此不会复制缓存实现或产生两套缓存目录。

## 特殊资源处理

### Hillshade

hillshade 元数据和最终图片 URL 都必须经过统一瓦片 URL 解析。不能只把元数据请求发往 `5001`，却让其中的相对图片 URL 按页面 origin 回到 `5000`。

### Terrain `parentUrl`

应用内部基础 terrain 父级引用不得保存或输出 `http://localhost:5000/...`。远程访问时该地址会错误指向客户端本机，也会绕回主连接池。生成 `layer.json` 时应输出应用内路径或继承 tile origin 的地址，并兼容已有数据库中的旧绝对值。

### Socket.IO

Socket.IO 必须始终连接主 origin。专用瓦片端口不开放 `/socket.io/`，也不参与 WebSocket upgrade。

## 错误处理与降级

- 端口绑定失败：写入明确日志，描述符不宣告专用端口，主服务正常运行。
- 客户端不可达：健康探测超时后回退同源，不阻塞页面启动。
- HTTPS 页面：没有显式 HTTPS 瓦片 origin 时直接同源，避免 mixed content 或错误 TLS 握手。
- 瓦片自身返回 `404`、`204` 或上游错误：沿用现有 Cesium 和路由错误语义，不把资源错误误判为整个瓦片 origin 不可达。
- WSGI/测试 import：不启动额外监听端口，保持测试隔离和现有部署兼容。

## 缓存

继续使用现有浏览器缓存头和工作区中的底图磁盘缓存实现：

- 底图缓存按源版本隔离；
- 正常源、回退源和旧版本继续使用各自现有 `Cache-Control` 语义；
- 地图任务、等高线和 terrain 静态产物继续使用 immutable 缓存；
- `5000` 与 `5001` 复用同一服务端缓存目录，不重复下载同一缓存命中的底图。

缓存主要降低重复访问成本；连接池隔离负责解决首次访问新区域时的 API 饥饿，两者互补但不互相替代。

## 安全与兼容性

- `5001` 与当前主服务使用相同监听主机，局域网部署时需要与 `5000` 一起考虑防火墙。
- CORS 仅服务只读瓦片和健康检查，不在专用端口开放可变更状态的 API。
- 现有同源 URL 继续有效，旧书签、测试和不经过 `run_server()` 的部署不会失效。
- HTTPS/反向代理部署默认走同源；后续可单独提供 HTTP/2 代理配置，而不要求桌面用户改变运行方式。

## 测试策略

### 后端单元与集成测试

1. 专用服务只允许瓦片前缀和 `/tile-health`，API 与页面路径返回 `404`。
2. 允许的响应包含正确 CORS 头，原有缓存头不丢失。
3. 使用真实临时端口验证 HTTP 请求可以访问健康检查和代表性瓦片路由。
4. 模拟端口占用，验证主服务继续运行且描述符回退同源。
5. 验证 WSGI import 不启动监听线程。
6. 验证底图缓存命中不会再次回源，且两个端口复用同一缓存。

### 前端契约测试

1. 地图、历史、任务瓦片、等高线、terrain 和 hillshade 全部使用统一 URL 解析入口。
2. HTTP 页面健康探测成功后使用 `5001`。
3. 端口缺失、探测失败和 HTTPS 页面使用同源。
4. Socket.IO URL 不经过瓦片 URL 解析。
5. terrain 父级地址不会固定指向 `localhost:5000`。

### 回归测试

运行与以下模块相关的 pytest：

- tile server；
- basemap proxy 和磁盘缓存；
- map/history/tasks JavaScript 契约；
- terrain、hillshade 和本地 terrain 预览；
- Socket.IO 单例；
- 应用启动与运行模式。

实现完成后必须先运行上述定向 pytest，再运行完整 pytest；如果完整测试因明确的外部环境条件无法执行或失败，完成报告必须列出具体命令、失败输出和未验证范围。Nuitka/CI 冒烟增加对专用端口健康检查的验证，同时保留只启动 `5000` 也能工作的降级验证。

## 验收标准

1. 普通 HTTP 桌面启动后，浏览器开发者工具中 API 与 Socket.IO 请求发往 `5000`，应用瓦片请求发往 `5001`。
2. 冷地图同时产生超过 6 个瓦片请求时，任务和配置 API 不再等待瓦片连接池释放后才发出。
3. `5001` 被占用、被防火墙阻断或未启动时，刷新页面后地图仍能通过 `5000` 加载。
4. HTTPS/反向代理访问不会尝试连接明文 `5001`，页面保持可用。
5. hillshade 和 terrain 父级资源不会意外绕回错误 origin。
6. 相关自动化测试通过，现有瓦片缓存和 Socket.IO 行为无回归。

## 后续工作

服务器或公网部署可另行提供 Caddy/Nginx HTTPS + HTTP/2 示例，通过单一公开 origin 获得多路复用，并配置 Socket.IO upgrade、上传大小、超时和鉴权。该部署增强不属于本次桌面版连接池隔离实现。
