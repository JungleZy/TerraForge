## 01 · 证据

### A. 可读性：全站只有两处真实对比度失败，成因同一个

逐元素扫描（首屏 + 四张面板 + 命令面板 + 速查表 + 两个弹窗 + 确认框，明暗各一遍）：

| 位置 | 主题 | 前景 | 背景 | 比值 | 需 |
|---|---|---|---|---|---|
| `.cmdk__help-row kbd`（速查表 5 颗）+ `.cmdk__item kbd`（命令面板 3 颗） | 暗 | `#9aa0aa` | `#adb5bd` | **1.27** | 4.5 |
| 同上 8 颗 | 亮 | `#4d5562` | `#212529` | **2.05** | 4.5 |
| `span.small.text-secondary`（插件卡元信息，`plugins.js:86`） | 暗 | `#6c757d` | `#15171c` | **3.82** | 4.5 |

像素采样交叉验证：暗色下五颗徽章渲染成**五个空白浅灰矩形**（徽章内填采样 `(169,177,186)`，字形不可见）；亮色下 `?`/`+`/`-` 三颗是**三个纯黑小方块**。

其余全部通过，且余量很大：8 个文字令牌 × 4 档面 × 2 主题 = 80 项矩阵里，`--color-text-primary` 11.98–16.18、`--color-text-secondary` 5.49–7.52、面板说明文字亮 7.52 / 暗 5.49、状态栏亮 7.31 / 暗 6.99。矩阵里失败的 11 个组合（`text-muted` 全档、亮色 `warning` 对页面底 4.40）**在界面上没有任何真实文字命中** —— 与 `style.css:53-61` 自述的「muted 不是文字色」一致。

**占位符是第二个「令牌没接管」的家族**：`.form-control::placeholder` 规则只覆盖 `.form-control`（`style.css:3702-3704`），而 `#placeSearchInput`（`.map-search__input`）与 `#cmdkInput`（`.cmdk__input`）都不是 —— 两者实测吃 Chromium UA 默认 `rgb(117,117,117)`：亮 4.48 / 暗 3.99（搜索框）、暗 3.13（命令面板）。走规则的那批实测 6.76。

### B. 操作便利性

**B1. 读数不跟着选区走（我独立复现，两半）**

```
手动输入四至「确定」→ #tileEstimate: hidden=true, text=""      ← 不出数
碰一下 #zoomMax     → #tileEstimate: hidden=false, 「预计 25,545 张瓦片」
点「清除选区」      → #tileEstimate: hidden=false, 「预计 25,545 张瓦片」  ← 陈旧
                      同一格读数已回到「请在地图上框选下载区域」
```

`updateTileEstimate()` 的 8 个调用点（`map.js:816` 区域导入 / `:941` 区域预估回来 / `:1526` 地名搜索 / `:2012` 切管线 / `:2069` 缩放输入 / `:2087` MBTiles 勾选 / `:3354` 打开面板 / `:3411` 提交前）里，**没有一个是选区变化路径**：`_applyManualBounds`、`clearSelection`、框选落定（`map.js:1827` 的 LEFT_UP）、拖角点（`_syncBoundsFromRect` → 只到 `updateBoundsInfo`）全部不在其中。

**B2. 键盘用户无法完成主任务的第一步**

框选矩形的三个回调分别绑 `LEFT_DOWN`(`map.js:1734`) / `MOUSE_MOVE`(`:1769`) / `LEFT_UP`(`:1827`)，**没有键盘分支**（`map.js` 里的 `keydown` 监听只有：四至编辑输入框 `:1603`/`:3111`、缩放键 `:1858`、手动四至 `:4347`）。实测：Ctrl+K →「开始框选」→ Enter 后 `canvas.style.cursor` 变 `crosshair`（模式确实开了），但可聚焦元素集合不变，连敲方向键/Enter/Space 后 `#statusSelection` 读数**没有变化**。

替代路径存在且完整：「手动输入范围」实测键盘全程可达（Tab×7 + Enter → 四个输入 → Enter → `#statusSelection` 变「已选区域 0.300° × 0.300°」+ `#boundsAnnounce` 播报四至 + 焦点落「清除选区」）。13 项主要动作里 **12 项键盘可达、1 项（框选）不可达**。

**B3. 清除选区零播报，且留下过期播报**

实测：清除后 `#boundsAnnounce`（`role=status aria-live=polite`）文本**仍是**「已选定下载范围：北纬 30.50000…」。读屏用户拿到的是一条已经不成立的播报，而清除这个动作本身没有任何播报。

**B4. 校验失败只有 toast，字段侧零标记**

提交缺选区 → `app-toast--warning`「请先在地图上框选下载区域，或用选区那一格的「手动输入范围」填写四至」。同时 `#createPanel .is-invalid, [aria-invalid="true"], .invalid-feedback` 查询结果**长度 0**，`#createTaskBtn` 无 spinner 态。缺任务名时更弱：被浏览器原生 `required` 拦下，`validationMessage` 是**英文** `"Please fill out this field."`，而 `aria-required`/`aria-invalid`/`aria-describedby` 全为 `null`，600 ms 内无任何 toast。

**B5. 焦点归还：四张面板对，三处对话框不对**

| 浮层 | Escape 后 `activeElement` | 归还触发钮 |
|---|---|---|
| 四张 `.workbench-panel` | 对应的 `.map-panel-btn` | ✅ |
| `.cmdk__dialog` / `--help` | `BODY` | 无 DOM 触发钮 |
| `#taskDetailModal` / `#pathBrowserModal` / `.app-confirm` | `BODY` | ❌ |

确认框那条做了根因取证（打桩日志）：`guard` 的 `disabled=true` 触发 UA unfocusing → 焦点离开触发钮；`ui.js:610-614` 的焦点收尾在 `finally` 求值时，焦点还在确认框的「取消」上（覆盖层要等 `ui.js:332` 的 300 ms 定时器才移除），守卫条件 `active === document.body` 不成立 → 归还分支被跳过；300 ms 后 `finish()` 把焦点交给 `body`。即 `ui.js:597-605` 注释声明的「由制造这次焦点丢失的 guard 自己收尾」在**确认框这条路径上没有发生**。

### D. 术语与诚实性

**诚实性的底子是好的（全量扫描结论）**

- 夸大宣传 **零命中**（20 个 catalog 文件 3934 行，按 26 个最高级词扫值行；唯一命中 `applies instantly` 描述的是实际行为）。
- 黑暗模式 **零命中**：强制连续 / 假稀缺 / 羞辱式确认三类全部零命中；删除确认的「同时删除磁盘产物」**默认不勾**（`history.js:1233-1236`，实测 `checked=false`）；破坏性确认的静息焦点在**取消**（实测 `.app-confirm__btn--cancel`）。
- 披露到位：切片档位写明「3.3 倍体积换 2.8 倍精度」、法线写明「+35%~100% 体积、约 2 倍时间、切完想开只能重新切片」、MBTiles 写明「松散瓦片目录照常保留」、超 10 万张预告「创建时将要求确认」。

**标签↔行为不符 5 条（上一轮两条已修：工具条「下载」→「新建」、浮层「删除」→「清除选区」）**

1. 「用它切地形」（`js_history.py:119-121`）实际只**开一张表单**（`task_list.js:551` → `map.js:2717` → `openCreatePanel`），点完什么都没切。
2. 组头「数据范围 / Data extent」（文案 `tpl_index.py:115-118`，渲染点 `templates/index.html:207`）对四条管线共用，但 `local_terrain`/`contour` 下它盖着的是「数据来源」下拉 + 上传 tif，**一个 extent 都没有**。这条不是推断——catalog 自己的注释就写着这个键管的是「数据范围 / 来源」两件事（`tpl_index.py:107`），即拆组时已知它一键双用，zh 侧只挑了其中一个含义当标签，en 侧 `Data extent` 把另一个含义丢得更干净。
3. 「鼠标指向地图显示经纬度，点击复制坐标」（`tpl_index.py:498`）**无条件承诺**，而 `map.js:4276` 是 `if (!lastCoords) return;` —— 实测在鼠标从未进过地图时点击：toast 数 **0**，完全静默。（旁边的选区胶囊 title 写了「框选后点击」，有条件限定，是对照组。）
4. `dem_hint`「下方 NUM/SWB 仅 ASTER 适用」（`tpl_index.py:246-250`）指着一个**永久不可见**的控件：`#demDownloadSwb` 被 `map.js:2036-2042` 在初始化时无条件 `disabled=true` + 外层 `.form-check` 设 `hidden`，实测 `display:none`、`getBoundingClientRect()` 全 0。
5. `#tileEstimate` 的陈旧读数（见 B1）—— 屏上同时存在「请在地图上框选下载区域」与「预计 25,545 张瓦片」。

**术语（可读性的第二半）**

## 03 · 裁定

**REDESIGN。** 总分 13/30 低于 20，且 #9 得 0 —— 按 `design-is` 的裁定规则机械得出，不因「上一轮刚重做过」而回调。

**但重做的对象必须说清楚，否则这个判决会被执行错。** 本轮证据显示：结构层（IA、令牌、层栈、焦点顺序、死代码）**已经达标**，把它们再推一遍是纯损失。失分集中在三个与结构无关的层：

1. **交付层**（#9=0 的唯一原因）：6.51 MiB 未压缩载荷 + 3.8 s 不可跳过的 splash 遮挡一个 130 ms 就绪的 DOM。
2. **Bootstrap 继承边界**（#3、#4 的一半）：令牌只接管前景不接管背景 → `kbd` 灰压灰、两个占位符落回 UA 灰、插件卡吃 `.text-secondary`、`.alert-warning` 由 Bootstrap 上色而项目令牌空转。
3. **术语与状态的自洽**（#4、#6、#8）：一个概念 6 种叫法、13 个术语无解释、5 条标签↔行为不符、读数不跟着选区走。

### 最高杠杆的 5 个动作

1. **#9 交付层**：给静态资源开压缩（Cesium.js 5.64 MiB → gzip 后约 1.5 MiB 量级），并让 splash 可点击/按键跳过、把 3 s 放人上限收短。证据：`curl` 实测无 `Content-Encoding`；`map.js:458-463` 的 `tilesLoaded` 钩子接对了但 `:467` 的 3 s 上限先到（3844 ms vs 末块瓦片 4428 ms）；splash 上零事件监听。**注意**：`:464-466` 有就地登记说明这个上限是刻意的（慢网络下不想把人关在开屏里），改动要保住那条意图，不是删掉上限。
2. **#3/#4 继承边界**：给 `kbd` 补 `background`（`style.css:4488-4497`），给 `.map-search__input` / `.cmdk__input` 补 `::placeholder`（`:2204-2217`、`:4447-4457`），把 `plugins.js:86` 的 `.text-secondary` 换成项目令牌。这三处是同一个根因的三个出口。
3. **#6 读数跟着选区走**：把 `updateTileEstimate()` 接进 `_applyManualBounds` / `clearSelection` / 框选落定三条路径（`map.js:139` 的 8 个调用点里现在都没有），顺带让 `clearSelection` 播报一次并清掉 `#boundsAnnounce` 的过期文本。
4. **#2 键盘能画框**：给 `#createBoundsReadout` 或地图容器补一条键盘定框路径（方向键调四至 + Enter 落定），或把「手动输入范围」提升为与「去框选」等权的首要入口而不是并列的第二颗按钮。证据：`map.js:1734/1769/1827` 三个回调全绑鼠标事件。
5. **#4/#10 术语与入口**：把「层级」六种叫法归一（含 `tpl_index.py:462` 的 hint 与 `:146` 的字段标签同名）、给 13 个无解释术语补 `.hint`、把「数据源」的两个含义拆成两个词（en 侧尤其）；同时收敛 21 个冗余入口里最没必要的那批（打开同一张面板的 6 条路）。

**明确不做**（这一轮的 anti-scope）：不动 IA（四条管线一张面板、非模态、层栈）、不动几何令牌与间距刻度、不动焦点顺序与 Escape 归还（四张面板那部分已达标）、不动 Cesium 本身的选型。

- 3.8 s 不可跳过的全屏 splash。证据：splash 上零事件监听；map.js:458-463 的 tilesLoaded 钩子接对了，但 :467 的 3 s 放人上限先到（splashDone 3844 ms vs 末块瓦片 responseEnd 4428 ms）；工具条可点时刻与 splash 让位时刻差 0.1–0.9 ms。注意 :464-466 有就地登记说明上限是刻意的，不要当成缺陷删掉。导致 #9 = 0、#5 扣分。
- 令牌只接管前景不接管背景的做法。证据：style.css:4488-4497 的 kbd 规则写 color 未写 background → 暗 1.27:1 / 亮 2.05:1；.form-control::placeholder（:3702-3704）覆盖不到 .map-search__input 与 .cmdk__input → UA 灰 3.13–4.48:1；plugins.js:86 用 Bootstrap .text-secondary → 3.82:1。导致 #3 = 1。
- 读数与选区状态解耦。证据：updateTileEstimate() 的 8 个调用点（map.js:816,941,1526,2012,2069,2087,3354,3411）里没有一个是选区变化路径；实测清除选区后屏上同时有「请在地图上框选下载区域」与「预计 25,545 张瓦片」。导致 #6 = 1。

重做的优先级顺序：
