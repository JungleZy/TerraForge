# DOM 局部更新优化

## 问题描述

之前每次 WebSocket 推送数据时，都会重新渲染整个任务卡片，导致：
- 整个 DOM 节点被替换
- 页面出现闪烁
- 性能浪费
- 用户体验不佳

## 优化方案

### 智能更新策略

根据数据变化类型，采用不同的更新策略：

1. **状态变化**（status 改变）→ 完整重新渲染
   - 原因：按钮需要改变（开始 ↔ 暂停 ↔ 恢复）
   - 影响：整个卡片结构变化

2. **进度变化**（downloaded_tiles 改变）→ 局部更新
   - 原因：只有数字和进度条变化
   - 影响：只更新进度条和下载数量

3. **无变化** → 不更新
   - 原因：数据没有变化
   - 影响：无

## 性能对比

### 优化前
每次进度更新都替换整个 DOM 节点，触发完整的重排和重绘。

### 优化后
进度更新只修改进度条宽度和文本内容，只触发局部重绘。

## 优势

1. **性能提升**：减少 DOM 操作、HTML 解析、重排和重绘
2. **用户体验**：无闪烁、更流畅、响应更快
3. **资源节约**：降低 CPU 和内存占用
