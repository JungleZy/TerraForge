# TerraForge - 可执行文件分发说明

本目录包含 TerraForge的独立可执行版本。

## 快速开始

### Windows
1. 解压 `terraforge-windows.zip`
2. 双击 `terraforge.exe`
3. 打开浏览器访问 `http://localhost:5000`

### macOS
1. 解压 `terraforge-macos.tar.gz`
2. 打开终端，进入解压后的文件夹
3. 运行：`./terraforge`
4. 打开浏览器访问 `http://localhost:5000`

### Linux
1. 解压 `terraforge-linux.tar.gz`
2. 打开终端，进入解压后的文件夹
3. 运行：`./terraforge`
4. 打开浏览器访问 `http://localhost:5000`

## 功能特性

- 无需安装 Python
- 无需安装依赖
- 可移植 - 可复制到任何机器运行
- 所有依赖已打包

## 系统要求

- **Windows**: Windows 10 或更高版本（64位）
- **macOS**: 仅支持 Apple Silicon (arm64)。发布包在 Apple Silicon 机器上构建，Intel Mac 无法运行，需自行[从源码构建](BUILD.md)
- **Linux**: 与 ubuntu-latest（发布包的构建环境）同等或更新的 64 位发行版

## 目录结构

```
terraforge/
├── terraforge(.exe)    # 主程序
├── templates/              # Web 界面模板
├── static/                 # CSS、JS、图片
├── gdal-data/              # GDAL 数据文件
├── proj-data/              # PROJ 坐标系数据文件
├── data/                   # 数据库（自动创建）
├── downloads/              # 下载的地图（自动创建）
└── cache/                  # 瓦片缓存（自动创建）
```

**移动或复制时必须整个 `terraforge/` 目录一起搬。** 程序在自身可执行文件所在的目录里查找 `gdal-data/` 和 `proj-data/`（坐标转换与栅格读写的必需数据）。只把可执行文件单独拷出来，启动时会直接报错退出：`Corrupt bundle: missing GDAL/PROJ data directories`。

## 配置说明

应用首次运行时会自动创建必要的目录：
- `data/` - SQLite 数据库
- `downloads/` - 下载的地图文件
- `cache/` - 瓦片缓存以提高性能

## 故障排除

### 端口已被占用

⚠️ **切勿同时运行两个 TerraForge 实例。**

第二个实例确实会因为端口冲突而退出，但它在退出**之前**已经完成了数据库初始化、启动清扫和四条任务管线的孤儿任务恢复——这些动作都发生在绑定端口之前。后果是：它会删掉第一个实例**正在使用**的临时工作目录，并把第一个实例正在跑的任务状态改写成"中断后恢复"的样子。正在下载的任务因此损坏，且无法自动挽回。

所以，如果启动时提示端口被占用：先确认不是自己已经开着一个 TerraForge（检查任务管理器 / `ps`），再去处理其他占用 5000 端口的程序。

监听端口固定为 5000，**不可配置**——配置页面和配置文件里都没有改端口的选项，不必去找。

另有一个瓦片专用端口 5001（5000 + 1，同样不可配置）：底图、地形、等高线和历史任务预览的瓦片请求都走它，躲开浏览器对单源的 6 连接上限，否则首屏瓦片风暴会把页面上一切 API 操作堵在浏览器连接池里排队（见 `src/core/tile_server.py`）。

5001 **不是主服务的第二个入口**：它只放行 `/basemap/`、`/tiles/`、`/terrain/`、`/contour/` 四个瓦片路径前缀和一个 `/tile-health` 健康检查，其余请求（页面、静态资源、以及所有 `/api/` 接口）一律 404。

**5001 只要不可用就一律退回 5000 同源出图**，但触发方式分三种，判定的位置不同：

- **端口起不来**（被别的程序占了、被安全软件拦住绑定）：服务端在启动时就知道了，当场记下降级，页面从第一张瓦片起就走同源，不做任何等待或重试。
- **端口起来了、客户端却够不着**（防火墙拦入站、NAT / 反向代理只转发了 5000、从另一台设备访问）：服务端无从知情，只能由浏览器判断——每次打开页面探一次 `http://<主机>:5001/tile-health`，**1 秒内**没拿到正常响应就整页退回同源。探测结果在当前页面内缓存，只在**重新加载页面**时重新判定，所以调整防火墙或转发规则之后要刷新一次才生效。
- **通过 HTTPS 访问**（前面挂了反向代理）：页面根本不会去探这个明文监听端口——混合内容本来就会被浏览器拦掉——始终保持同源。

降级只影响**性能**，不影响功能：瓦片照常出图，只是重新去挤主端口那 6 条连接，首屏瓦片多的时候页面上其他操作会跟着变慢。因此在只放行 5000 的环境里部署完全可行，不必为 5001 专门开洞。

### 防火墙警告

首次运行时系统防火墙会询问是否允许接受传入连接。**这不是一个例行的无害提示，请先读完下面这段再决定。**

TerraForge 监听 `0.0.0.0:5000`（瓦片端口 5001 同理），即接受来自局域网任意机器的连接，且**没有任何登录或鉴权机制**。它的 API 可以读写本机任意磁盘路径、并能删除目录。程序启动时还会在控制台主动打印局域网访问地址。点"允许"，等于把上述能力开放给同一网络内的所有人。

建议：

- 在**咖啡馆、酒店、公司公共 Wi-Fi 等不受信任的网络**下，选择"拒绝"，或只勾选"专用网络"。
- 拒绝**不影响任何功能**——本机浏览器通过 `http://localhost:5000`（即 127.0.0.1）访问，走的是回环地址，不经过防火墙的入站规则。瓦片端口 5001 同理；即使只有它单独被拦，瓦片也会按上文「端口已被占用」里的第二条自动退回同源，代价只是速度。
- 只有在你确实需要用**另一台设备**访问本机的 TerraForge 时，才需要允许，并请确保处在可信网络中。两个端口都无鉴权，但敞开的面不一样：**5000 是完整的 API 入口**（读写任意磁盘路径、删除目录都在这里），**5001 只出瓦片**（四个瓦片前缀加健康检查，其余 404），真正需要谨慎对待的是 5000。只放行 5000 也能正常使用（瓦片自动降级），放行 5001 换来的只是瓦片分流带来的流畅度。

关于 5001 还有一条与防火墙无关、0.3 之前不存在的能力，需要单独说明：

**5001 对它的每一个响应都带 `Access-Control-Allow-Origin: *`**，包括 404。换端口对浏览器就是跨源，不带这个头的话 Cesium 取瓦片和 `layer.json` 会直接失败（而且失败会被浏览器报成一句 CORS 错误，真实状态码看不见）—— 但它同时意味着：**你在浏览器里打开的任意一个网页，都可以跨源读取 5001 上的内容**。5000 没有这个头，跨源页面拿不到它的响应体。

具体边界：

- 能被读到的只有 5001 放行的那四类瓦片和 `/tile-health`，也就是**底图瓦片、已下载任务的瓦片、地形与等高线瓦片**；`/api/` 全部 404，任务列表、配置、磁盘路径都读不到。
- 只有读，**没有写入面**：这些路由只注册了 GET，跨源页面无法通过 5001 创建任务、改配置或删文件。
- 泄露的是「这台机器上存在哪些瓦片、内容是什么」——比如探测某个任务 ID 的瓦片是否 200，从而知道你下过哪片区域。
- 注意这一条**与防火墙无关**：跨源读取来自你本机浏览器里打开的页面，走的是回环地址，防火墙的入站规则拦不到（同上文「拒绝不影响任何功能」的道理）。想彻底去掉这条能力，只能让 5001 起不来——比如让别的程序先占住这个端口，TerraForge 会自动退回 5000 同源出图，功能不变、只是慢一点。

### macOS 安全警告

从网络下载的未签名程序会被 macOS 标记隔离属性，表现为"已损坏，无法打开"或直接被拦截。进入解压出的 `terraforge` 文件夹，执行：

```bash
xattr -cr .
```

注意这里清的是**整个目录**（`.`），而不是只清可执行文件——同目录下的动态库同样带着隔离标记，漏掉它们程序照样起不来。

如果仍被阻止：

1. 打开"系统设置" → "隐私与安全性"
2. 在底部找到被拦截的提示，点击"仍要打开"

注意：如果你用的是 **Intel Mac**，报错的根源是架构不匹配（发布包为 arm64），不是安全策略——反复调整安全设置没有用，请参见上文「系统要求」。

### Linux 权限错误
如果遇到权限错误：
```bash
chmod +x terraforge
```
